### How the 234 concept quiz items are used today

All six consumers read the same per-concept list; there is no item pool, band, pattern or
misconception field.

| Consumer | Selection | File |
|---|---|---|
| Concept quiz (`quiz:`) | First 5 by `(difficulty, id)` | `learn/quizzes.py:choose_items` |
| Review / remedial | 3 / 4 random (seeded) | same |
| Module checkpoint | Staircase on `difficulty` across the module's items, avoiding items seen in 14 days | `learn/quizzes.py`, `planner/gates.py` |
| Placement | Binary search over the prerequisite order; items nearest difficulty 2; boundary confirmed with a second item | `placement/engine.py` |
| Weekly assessment | Weighted by exposure and weakness, `_pick` by target difficulty, plus due reviews and 1–2 judged problems | `assessments/service.py` |
| Learning sessions | Use atom `steps`, not concept quiz items | `learn/sessions.py` |

Measured: 234 items (Zero 74, DSA 93, CP 67); 214 `mcq`, 20 `output`, 0 `bug`;
difficulty 1/2/3 = 82/114/38 (nothing at 4–5); all have exactly 4 options; 18 have code in
all three languages; **item IDs are unique only within a concept** (225 distinct of 234), so
a global key must be `course:concept:item`.

## 5. Schema drafts (Pydantic, repo style)

```python
class SourceRef(Model):           # one adapted source
    title: str; author: str; url: HttpUrl
    license_spdx: str; license_url: HttpUrl
    retrieved_at: date; content_sha256: str = Field(pattern=r"^[0-9a-f]{64}$")
    source_id: Slug                # must exist in content/sources/registry.yaml

class Provenance(Model):          # optional everywhere; absent == legacy record
    origin: Literal["original", "adapted", "linked", "partnered"] = "original"
    author: str = "Socrat Learning"
    authors_adapted_from: list[SourceRef] = []
    review: Review | None = None   # existing Review(by, at, notes); never filled by tooling
    version: int = 1
    rights: str = "Socrat original, all rights reserved"
    attribution_md: str = ""
    # validator: origin == "adapted" requires >= 1 SourceRef whose registry entry is
    # license_status: verified and action allows adaptation

class Pattern(Model):
    id: PatternId                  # "dsa:sliding-window/variable-size"
    concept: QualifiedRef          # must exist in the catalog
    title: str; tracks: list[Literal["foundations", "interview", "competitive"]]
    recognise: list[str] = Field(min_length=3, max_length=3)   # <= 60 words total
    state: str = ""; transition: str = ""; base_cases: list[str] = []
    complexity: Complexity
    variants: list[Variant]        # {id, band 1..7, problem: native id | external id | None}
    pitfalls: list[Slug]           # misconception IDs (taxonomy-checked)
    atoms: list[Slug]              # atom IDs in the concept's atom pack
    quiz_family: str               # must resolve to a quiz family file
    problems: PatternProblems      # native: [Slug] (must exist); external: ["leetcode:<slug>"|"cf:..."|"cses:..."] (must exist in the index)
    showcase: list[str] = []
    status: Literal["provisional", "calibrated", "retired"] = "provisional"
    provenance: Provenance

class QuizFamily(Model):
    id: str                        # "quiz:dsa:sliding-window:fixed-window-sum"
    concept: QualifiedRef; pattern: PatternId | None
    format: ItemFormat             # mcq | output_prediction | trace | fill_blank | parsons | bug_spot | edge_cases | complexity | classify | counterexample
    tracks: list[Track]; languages: list[Language]
    generator: GeneratorSpec | None   # template, params, reference, seed ranges per pool
    items: list[BankItem] = []     # static items (existing 234 wrapped here, read-only)
    distractors: list[DistractorRule]   # {rule, misconception} — misconception taxonomy-checked
    hint_ladder: list[str]; time_limit_s: int
    status: Literal["provisional", "calibrated", "retired"] = "provisional"
    provenance: Provenance

class BankItem(Model):             # one servable item, static or generated
    id: str                        # global: "<course>:<concept>:<item>" or family+seed
    band: int = Field(ge=1, le=7); difficulty_prior: int
    pool: Literal["practice", "assessment"]
    status: Literal["provisional", "calibrated", "retired"] = "provisional"
    misconceptions: list[Slug] = []
```

Existing models gain only **optional** fields (`provenance: Provenance | None = None` on
`Concept`, `QuizItem`, `Problem`; `AtomPack` unchanged), so all current files stay valid and
the catalog digest changes only when someone adds the field.

## 6. Runtime persistence (migrations)

Item definitions stay in files, like the existing quiz items. Only runtime state goes to the
database. One additive, reversible migration in M2 (number depends on D1):

| Table | Columns |
|---|---|
| `quiz_responses` | id, enrollment_id, item_id, family, pattern, concept, mode, pool, session_id, correct, score, hint_level, time_s, seed, created_at |
| `learner_abilities` | enrollment_id, pattern, theta, n, updated_at (PK enrollment+pattern) |
| `item_ratings` | item_id, d_current, n_responses, updated_at (provisional items only; frozen when calibrated) |
| `item_calibrations` | item_id, status, pct_correct, discrimination, distractor_counts JSON, median_time_s, computed_at, approved_by, approved_at |

`approved_by` is set only by an explicit human action (CLI with the operator's name); no code
path fills it.

## 7. Feature flags

`adaptive_quiz_enabled: bool = False` and `pattern_planner_enabled: bool = False` in
`Settings`, exposed in `/api/v1/features`, mirroring `explainer_enabled`. With both off:
no new routes respond (404), selectors and composer take their current code paths, and
golden tests pin the current outputs.

## 9. Gaps and conflicts found

1. **Assessment modes would have zero eligible items.** Rule 7 requires calibrated assessment-pool
   items only, but every existing and new item starts `provisional`, and calibration needs
   ≥ 30 responses plus human approval. (D3)
2. **Mastery model.** PRD §10.3 (Beta-Bernoulli per concept, implemented) owns mastery. content.md
   §8.5 adds an Elo θ per pattern and a mastery proposal. (D4)
3. **Track targets.** PRD §10.1 "preferred difficulty … roughly 65–80% success in learning
   mode"; content.md uses Competitive 0.60. (D5)
4. **Misconception taxonomy is mostly placeholders.** 31 IDs = `syntax-delimiters` + 30
   `<concept>-repair`. content.md's distractor rules need specific IDs (`window-off-by-one`,
   `stop-after-first`, …). (D6)
5. **"Sandbox".** Learner code runs in the gVisor broker; authored content is verified with
   the local authoring runner. (D7)
6. **Hint multipliers drift (pre-existing).** Code `ASSISTANCE = (1.0, .85, .7, .5, .3, .1)`
   vs PRD §10.3 `(1.0, .85, .65, .35, 0, 0)`. Not changed by this work; flagged.
7. **Atom-pack reviews.** All 30 released packs carry `review: {by: Owner, at: 2026-10-13}`.
   Not touched; a human should confirm these records are real sign-offs.
8. **Pool partition of existing items.** 3–5 items per concept: a 70/30 hash split leaves some
   concepts with 0 assessment items and some with 1–2 practice items. Only applies with the flag on.
9. **content.md §8.5 cold start vs Playbook**: none found; both say win-first.

## 11. Risks

- Item volume: 12 patterns × ≥ 12 items is achievable only with generators; M5 depends on M4.
- Engine accuracy test (±0.07 of target after 8 items) depends on the simulator's noise model;
  the test will fix seeds and report the distribution, not one lucky run.
- Content quality: everything ships `provisional` with `review: null`; a domain expert must
  review before learners see it as reviewed.
- Legal: LICENSE/NOTICE/ATTRIBUTION are drafts. Appendix A licenses marked ◻ stay `unverified`
  and cannot be adapted from.
- Scope: Foundry, UI redesign, Skill Passport, IRT, new problems and mastery-threshold changes
  are excluded.
