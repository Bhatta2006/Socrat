# M5 gate

Repository implementation and local validation do not imply hosted or launch approval.

| Requirement | Repository evidence | External acceptance still required |
|---|---|---|
| Deterministic prerequisite-safe plans | Pure engine, immutable replay inputs, 2,000 generated history scenarios with exact repeat plans | Learning review of target thresholds and policy calibration |
| Workload and recovery safety | Capacity/reserve tests, explicit feasible alternatives, recovery/confirmation commands | Learner comprehension and realistic time estimates |
| Stable selection and difficulty | Inventory filtering, cooldown/exposure rotation, bounded independent-evidence difficulty controller | Content coverage and operational runtime health after M6 |
| Auditable and atomic changes | SQLite immutable-trigger checks, ownership/CSRF, idempotency, optimistic revisions, protected replay; PostgreSQL rehearsal test | Hosted CI PostgreSQL race result and staging backup/restore at schema `0005` |
| Reviewable learner journey | Plan creation, schedule review, confirmation, lighter-day, pause/resume, recovery UI | Product and accessibility sign-off on released content |
| Operational readiness | Feature flag defaults off in staging; historical revisions retained; rollback instructions | Staging flag rollout, monitoring ownership, drill and private approval references |

Real DSA launch content is not included. Synthetic fixtures establish deterministic behavior, never learning-effect evidence. M0–M4 open approvals remain open. M5 requires hosted/staging and accountable Product/Learning, Security/Privacy, and Engineering/Operations review before launch.
