# M7 learning sessions

Enable `SOCRAT_LEARNING_SESSIONS_ENABLED=true` to expose the Today session API/UI. It defaults off; local Compose enables it and staging defaults off. This does not enable execution. Code sessions require the existing M6 execution configuration and healthy worker capabilities. M7 adds no executable learner-code path in the API.

Apply Alembic revision `0007` before starting the new application. Backup/restore defaults now expect `0007`; use an explicit expected revision for older archives. To roll back exposure, disable the session feature and retain the database records. Do not downgrade a populated session schema as a routine rollback.

New plans generated while the session feature is enabled pin the additional [session planning policy](../../contracts/product/m7-session-planning-policy.json), version `1.0.0`. Older revisions omit that policy and retain their M5 replay. Competitive mixed sessions require at least 60 minutes of effective capacity, two different verified concept sets/families, and reviewed practice inventory that fits. Otherwise the planner keeps a single problem. Verified practice reserves 20% of working minutes for optional upsolve, in addition to the existing weekly reserve; session `planned_minutes` includes that allocation. Repair duration is a planning guide, not a hard deadline. Plan pause, content withdrawal, and the local-day cutoff still apply.

The plan may pin `repair_exercise_id` and `upsolve_minutes` on an independent block. Repairs obey prerequisite, calibration, language/runtime, difficulty, exposure, cooldown, family, and budget filters. `concept_gap`, `wrong_answer`, and `complexity` choose that concept-matched task if present. The new attempt starts from its starter code; the original draft remains saved. Other classifications and missing inventory copy the original draft. All repair evidence remains conservatively seen. This selection does not establish reviewed structural novelty or produce contest penalties/rankings. Refresh and confirm a plan to adopt the policy; existing sessions keep their pins. No migration beyond `0007` is needed.

Endpoints:

- `GET /api/v1/goals/{goal_id}/learning-session`: current learner-local day's session or `null`.
- `GET /api/v1/goals/{goal_id}/learning-sessions?limit=20`: owned summaries, newest first, bounded to 100; no answer/source artifacts. Expired/abandoned records flag recovery.
- `GET /api/v1/learning-sessions/{session_id}`: owned saved-session view, retaining unlocked content, saved responses and outcomes; withdrawn content remains blocked. Past sessions cannot resume or admit execution.
- `GET /api/v1/goals/{goal_id}/learning-session-telemetry`: versioned owned-goal export, meaningful participation, candidate activation and uncalibrated normal-session duration error; no answers, source, test data or reference solutions.
- `POST /api/v1/goals/{goal_id}/learning-session`: start with `curriculum_revision` and optional `timing` (`standard` or `untimed`). Retries return that day's existing session; a conflicting timing choice fails. Rest/content-gap days and stale/unconfirmed plans cannot start.
- `POST /api/v1/learning-sessions/{session_id}/commands`: `advance`, `pause`, `resume`, `abandon`, `start_timed`, or `upsolve`, with `expected_revision` and `idempotency_key`. Text blocks require a response except instruction. Exit requires a controlled reflection code. Independent/upsolve coding requires the phase's signed, healthy, completed Submit `run_id`. Upsolve requires `error_classification`.

Authentication, ownership, and CSRF match other learner APIs. Mutations lock the learner row on PostgreSQL. A repeated command with the same body returns its original receipt; reusing a key with different input fails. Content withdrawal also blocks receipt replay from exposing content. The browser reload button retrieves the latest progress after a revision conflict.

Blocks unlock sequentially. Only unlocked blocks expose prompts, explanation, or examples; reference solutions and hidden tests never appear in session views. Code drafts remain in M6 autosave storage. Operational failure preserves the draft and leaves independent work available for retry. Normal and upsolve blocks may advance after a healthy incorrect submission; a timed unsuccessful submission goes through error classification and upsolve first.

Text responses are retained in session progress and receipts, under the same learner-data access boundary. Free text remains ungraded. Reviewed choice/exact-trace checks receive local objective feedback, but neither kind is appended as mastery evidence. Reflection codes are controlled signals only. Session start/completion/block/command events enter the existing transactional audit/outbox without answer text. The owned-goal telemetry export counts sessions with valid finalized implementation evidence; passive/text-only sessions cannot qualify. It excludes invalidated practice facts and withdrawn content, and corrected diagnostic evidence cannot qualify activation. It is not a global reporting cohort.

`active_seconds` sums saved active intervals, excluding explicit pauses. When advancing coding blocks, duration stops at Submit admission rather than later result/Continue time. Entering upsolve also retains the original timed phase interval. It is not an inactivity detector or a calibrated duration metric. Session-bound implementation evidence measures solve duration using the command receipt at broker admission, excluding worker/queue latency and later session changes. The evidence schema retains its 45-minute cap; session-duration accounting retains the full interval. Duration error covers completed sessions without timed blocks, includes optional repair minutes only when repair is used, and always labels its estimates uncalibrated.

Expiry policy `local_day_1.0.0` closes commands and broker admission at learner-local midnight. History reads display the effective expired status without mutating records; a successful later session start durably expires prior unfinished sessions, closes saved active intervals at the cutoff and emits one expiry event. If start fails, its transaction rolls back these changes. Paused work can resume only on its original date. Refresh/recover and confirm today's plan to continue learning; saved blocks are never copied into a backlog. Completed sessions backed by valid implementation facts count as participation during recovery, without claiming graded explanation or mastery.

Telemetry definition `m7_participation_1.0.0` uses a candidate activation rule: completed/current diagnostic, confirmed plan, and the first finalized healthy independent Submit admitted within 48 hours of goal confirmation. Run, pending/failed worker results, upsolve-only work and text checks cannot activate. An eligible Submit may finalize after the 48-hour admission window. The older metric-contract plan-start wording needs Product reconciliation before aggregate publication; test/staff/synthetic/cohort exclusions are not inferred by this owned-goal endpoint.

The owner-selected [limited-pilot policy proposal](m7-limited-pilot.md) recommends this Submit definition and a sixty-second wrong-Submit practice penalty. Reviewer assignment, calibration and aggregate metric approval remain deferred. No unreviewed penalty is automatically pinned by this proposal.

## Track content and publication

See [session content authoring](m7-content-authoring.md) for the additive pack fields, objective validators and audit. Packs declaring `session_content_version=1.0.0` must contain reviewed lessons for new session blocks. Instruction renders the selected language's authored notes; Interview lessons require recognition, correctness and complexity sections. Guided examples are language-specific. Retrieval and exit checks expose prompts/choice labels only, and their exact answer keys stay private. An incorrect check still advances low-stakes learning, with feedback; it is not a mastery gate. Exit still requires a controlled reflection category.

New Competitive plans for these packs select structural repair only through an explicitly reviewed source/variant mapping, retaining all existing budget/readiness/exposure/runtime filters. A family change alone is insufficient. Legacy packs retain concept-matched behavior. A reviewed `competitive_penalty` is pinned at session start for standard Competitive practice: each healthy incorrect original timed Submit contributes its configured penalty seconds. Run, timeout, operational failure, untimed work and upsolve do not add penalties. Upsolve preserves the original result. This is practice feedback with no ranking; launch values require calibration and independent review.

The admin version response includes `learning_coverage`; the offline `learning-audit` command returns the same answer-free nine-cell report and exits nonzero for gaps. The separate `learning-plan-audit` command and authenticated admin endpoint rehearse the production fourteen-day planner across bounded readiness, exposure and schedule scenarios. Publishing a launch pack declaring session content requires both audits to pass plus the existing independent editorial, language and rights reviews. A planner audit failure leaves the pack staged and the active head unchanged. Legacy launch packs are compatible but do not acquire M7 coverage. No schema migration beyond `0007` is needed.

## Timed practice and upsolve

The planner decides which independent blocks are timed from verified readiness. Their window starts only with `start_timed`; its deadline is `start + block.minutes * 60`. Browser countdowns use server time for display. Broker admission is authoritative: `issued_at` must be before the deadline, and refreshing the page or repeating start commands cannot extend it. A timed block cannot pause after starting. Before it starts, normal pause is available.

Submissions admitted before the deadline retain eligibility while waiting for their worker result. The learner cannot start upsolve while that Submit is pending. A passing on-time result advances to the next planned block. An unsuccessful result can enter upsolve; a timeout with no Submit can enter upsolve after the deadline. Worker failures are labelled `unscored_operational_failure`, with no fabricated score. Timed text responses stay ungraded and cannot establish timed solving ability.

`upsolve` records a controlled category (`wrong_answer`, `implementation_bug`, `complexity`, `time_pressure`, `concept_gap`, or `unclear_prompt`). The browser first saves the latest editor source. The API creates a fresh practice attempt, copying that saved source for same-item repair or using the pinned repair task's starter code for a concept-matched variant. That attempt is explicitly seen (`unseen=false`); the old attempt and original timed outcome are retained. Samples and Submit from the old phase cannot be admitted again. Quotas, runtime capability, signatures, withdrawal, ownership, and kill switches remain enforced. Untimed upsolve supports normal pause/resume. A healthy finalized upsolve submission can advance even if incorrect; it is a learning attempt rather than a new contest result.

Choosing `timing=untimed` at session start removes practice timing and records the choice visibly. It provides a low-stakes access path; it neither approves an assessment accommodation nor proves timed performance. M9 owns assessment accommodation decisions. Optional upsolve allocations in new plans remain soft guides; learners may spend more time repairing. Historical sessions without an allocation retain their original behavior.
